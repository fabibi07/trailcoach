## 5. SOURCE_PROVIDER — contract implementation

| Method | `garmin_fit` behaviour |
| --- | --- |
| `authenticate` | Validates `account.auth_json["import_dir"]` exists; returns `auth_status="not_required"`, `file_count`. No credentials. |
| `discover_capabilities` | 15 `MetricCapability` rows (see §7) |
| `get_historical_range` | min/max `start_time` across FIT files |
| `initial_import(start, end)` | parses every `*.fit` (recursive), filters by date, returns paired `source_activities`/`activities` + `payloads`, `cursor` |
| `incremental_sync` | only files with `start_time > cursor_json["last_start_time_utc"]`; keeps cursor when nothing is new |
| `download_activity_file` | returns bytes of the file whose id matches |
| `get_wellness` | `[]` — activity FIT files carry no daily wellness |

Provider is stateless and DB-free. Corrupt files are reported in
`ImportResult.errors` and do not abort the batch.

**Source activity id**: `<serial_number>-<time_created UTC>` from the FIT
`file_id` message; falls back to the file SHA256 when either field is missing.
This makes a re-export of the same activity (possibly with different bytes,
e.g. re-downloaded from Garmin Connect) a `REIMPORT`, while the legacy
`fitfile` path keeps SHA256 ids.

## 6. FIT_PARSING

`FitParser.parse_bytes` (fitdecode) reads `file_id`, `device_info`, `record`,
`lap`, `session` → `FitDocument` with: start/created time, sport/sub_sport
(raw + canonical), summary (elapsed/moving/distance/ascent/descent/avg-max HR,
cadence, power), device (`manufacturer`, `product`, `serial_number`), canonical
stream rows (`t_s, elapsed_s, distance_m, lat, lon, altitude_m, speed_mps,
hr_bpm, cadence_spm, power_w, temp_c, running dynamics`), laps → `ActivityInterval`.

## 7. CAPABILITIES (generic metric names)

native: `heart_rate, gps, distance, duration, speed, elevation_gain, cadence,
power, temperature, running_dynamics` · derived: `pace` · unavailable:
`hrv, resting_hr, sleep_score, body_battery`. Upserted on every run
(`UniqueConstraint(source, metric)`).

## 8. RAW_DATA_FIRST / DEVICE / PROVENANCE

- Every FIT payload goes through `RawStore.store` (`raw/garmin_fit/fit/YYYY/MM/<sha256>.fit`), before any canonical row; `SourceActivity.fit_raw_file_id` set.
- `Device` upserted on `(athlete_id, serial_number, manufacturer, model)`; linked to `SourceActivity.device_id` and, if unset, `AthleteSourceAccount.device_id`.
- `DataLineage` (source, source_record_id, raw_file_id, device_id, account_id, timestamp, confidence, data_quality) merged into `SourceActivity.provenance` and `Activity.provenance`.
- `AthleteSourceAccount` is the only state store: `auth_status`, `cursor_json`, `health`, `last_success_at/last_error_at`, `consecutive_failures`. `SourceState` untouched.

## 9. DEDUP_INTEGRATION

Orchestrator per activity: `DedupeEngine.evaluate` →
`REIMPORT` skip · `AUTO_LINK` → `SourceActivity.canonical_activity_id = existing`, `ActivityLink(match_method="dedupe_auto", evidence=scores)` · `REVIEW` → new `Activity` flagged `dedupe_review_pending` + `DedupeReview.candidates` enriched with scores · `SEPARATE` → new `Activity`, `ActivityLink("primary")`.
Each activity runs in a `begin_nested()` savepoint; a failure counts as `failed` and does not roll back siblings.

## 11. ARCHITECTURE_FINDINGS

1. **Dedup calibration is strict.** With default weights (0.35/0.25/0.25/0.15)
   and `source_bonus ∈ {-0.05, 0, 0.10}`, the maximum score is 0.865 and
   `AUTO_LINK` (≥0.85) needs a near-perfect time match (<~26 s offset with
   identical distance/duration). Real Garmin+Strava pairs of the same activity
   typically differ by seconds–minutes and a few % → most will land in `REVIEW`.
   Not changed in P0.1 (engine is P0.0 approved); recommend recalibrating
   thresholds/tolerances once real multi-source data exists.
2. `MetricCapability` has no `athlete_id`: capabilities are per source, not
   per account/device. Fine for `garmin_fit`; a future device-dependent
   capability (e.g. running power) would need a per-account layer.
3. Legacy `source="fitfile"` rows are not migrated to `garmin_fit` (decision
   pending, see P0.0 scope message). Both paths coexist.

## 12. DESIGN_DECISIONS

- `ActivityPayload` keeps the `SourceProvider` contract generic: raw bytes,
  streams, intervals and device are all optional, so an API-only aggregator
  can return a summary-only `ImportResult`.
- "Credential" of a file provider = `auth_json.import_dir`; no new schema.
- Natural id from `file_id` rather than SHA256 (see §5).
- `init-db` unified on Alembic so no code path uses `create_all` in production.
